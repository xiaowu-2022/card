# U卡 WebView 过渡工程

这是独立的 uni-app CLI 工程，只负责打开线上 H5，不导入原 App 的业务页面。

## 打包

1. 用 HBuilderX 导入本目录 `mobile/webview-shell`，不要导入 `src` 或旧 `mobile/uni-app`。
2. 使用 Node.js 22。首次在另一台电脑打开时执行 `npm ci`。
3. `npm run typecheck` 检查，`npm run build:app` 编译 App 资源。
4. HBuilderX 中选择「发行 → App 云打包」，使用原签名材料。Android 覆盖安装需要原签名一致。

当前版本 2.5.07 / 2507。DCloud AppID `__UNI__30F90A0`，Android 包名
`cc.specpay.cards`，iOS Bundle ID `com.tng.pingqiu`。保留原图标。
签名证书不包含在工程中。编译资源不等于已经生成 APK / IPA。

## 网站与线路

`src/config.json` 集中配置内置域名、公司 slug、H5 入口和缓存键。
内置域名仅为 `27m.my`、`113b.my`、`18k.my`；2026-10-08 按用户要求移除
`specpay.cc`、`specpay.top`、`specpay.vip`。此调整不禁止服务器目录或已验证缓存
再次提供这些域名；若要停止动态发现，需在 Platform 中停用或解绑相应域名。
默认入口为 `https://选定域名/#/pages/login/index`。
部署前确保所有分配给该公司的域名均提供同一份 H5 和同源 API。

每次启动并发检测内置域名和缓存域名，读取 `/api/mobile/v1/domains`，
检查 HTTPS、公司 slug、已缓存的公司 ID 及域名自身是否仍在服务器列表中。
新列表替换缓存，不累积已解绑域名；新发现的域名也要检测。
每次启动、重试和重新连接都先测速，再打开本轮响应最快的可用线路。
缓存仅用于发现候选域名，不再优先保留旧线路；切换域名后可能需要重新登录。
每次回到前台，最多每分钟刷新一次列表缓存，不自动移动当前网页。
全部不可用时显示中文错误与重试，缓存不会绕过服务器验证。测速期间显示
“正在检测线路速度，选择最快线路”，完成后才创建并加载远程网页。

启动选线及网页加载期间显示本地黑金品牌欢迎页：“Spec Pay 万事达U卡 / 全球支付，尽在掌握。”，
卡片示意图随包内置，不依赖网络。移除常驻返回、刷新、线路工具栏；加载成功后网页占满状态栏下方区域。
加载超时或连接失败时在同一品牌页提供重试；“重新连接”会确认后重新进入登录页，可能需要重新登录。
Android 返回键优先回退网页历史，无历史时提示退出。
WebView 不注入 5+ 权限；业务使用 H5 的浏览器接口、Cookie 和原有服务端权限。
壳不保存账号密码、令牌，不替网页重发交易，也不注入脚本提交表单。

## 配套 H5

H5 登录页首次进入默认英文，右上角可切换公司已启用的语言；注册页沿用所选语言。
需要把本次 `public/h5` 部署到服务器。只换壳 APK 而没有部署 H5，线上仍会显示旧网页。
后续网页修改部署 H5 即可；修改内置种子、壳行为或原生权限需要重新打包。

本地已验证目录选择和缓存测试、类型检查、App 资源编译。发布前仍需真机验证：
登录保持、注册、身份证照片选择/上传、客服图片、流水、返回键及断网恢复。
本工程不宣称已完成 APK 签名或真机验收。

## 2026-10-09 冷启动窗口布局修正

针对冷启动登录页底部黑边、页面切换或键盘开合后可能恢复的反馈，父壳改为
固定视口，欢迎页在壳内滚动，不再靠欢迎页内容撑高父页面。子窗口明确采用
absolute 定位，收到网页就绪信号后先移除欢迎页，等待 Vue 完成布局更新，
再应用 top/bottom 边界并显示子窗口；回到前台时重新应用边界。
继续保留零 windowHeight 启动兼容、就绪检测和失败重试，过期回调不得显示旧窗口。

这是对启动显示顺序的修正，尚未证明就是用户设备黑边的根因。需要用
`mobile/webview-shell` 重新云打包、原签名覆盖安装，并验证冷启动、键盘、
登录后切换、前后台恢复及调试面板开关。仅部署 H5 不会应用此壳修改。
App 资源编译成功不等于已生成签名 APK；版本号当前未改。

## 2026-10-08 白屏入口修复

这些域名的站点根目录已经指向 H5 产物文件夹，访问入口必须是
`https://选定域名/#/pages/login/index`，不是 `/h5/#/pages/login/index`。
旧壳错误地加了 `/h5/`，服务器回退返回首页后，页面相对资源被解析为
`/h5/assets/...` 并返回 404，造成白屏。此前将其判断为服务器缺失资源不准确。
已验证 `https://27m.my/assets/index-Co5jBsxL.js` 返回 200 和 JavaScript
内容类型；无需为此修改服务器根目录或重新部署 H5 文件。

`src/config.json` 的 `entryPath` 已修正为根路径。`/api/mobile/v1/domains`
仍是公司线路接口，保留原有公司校验。`build-manifest.json` 仅是构建信息，
壳启动不请求它。不要把磁盘上的 `public/h5` 路径等同于公开 URL 路径。

壳代码同时增加单探测 4.5 秒、整轮 15 秒的独立超时，避免原生请求缺失
回调时无限等待。原生子窗口由父页面管理，不再对 append 后的窗口调用
独立 show/hide；通过内容区域尺寸控制网页展示，忽略空白文档的 loaded
事件，失败后保留重试界面。参考 [HTML5+ Webview append 约定](https://www.html5plus.org/specification/Webview.html)。

验证：`node --test tests/Frontend/webview-shell.mjs`（10 项离线测试，包含
实际入口配置的加载地址检查）、`npm --prefix mobile/webview-shell run typecheck`
和 `build:app`。这不代表签名 APK 或 OPPO 真机已通过。
入口修复需要从本工程重新云打包安装，旧 APK 内置路径不会随 Git 部署改变。
AppID 与版本保持当前 manifest 不变。


## 2026-10-08 欢迎页后黑屏修复（2.5.07）

2.5.06 将远程窗口初始化为 0px 高，并在原生 loaded 事件后直接撤掉欢迎页。
loaded 不能证明 H5 已渲染；此前测试仅模拟事件，未覆盖此情况。
2.5.07 从创建起采用 top/bottom 完整布局及 render:always，以透明度控制显隐，
不依赖启动期间可能未就绪的 windowHeight。只有检测到 uni-page-body 有可见
尺寸和文本、经过两次动画帧后才显示网页。检测只通过临时标题传递本轮就绪
标记，不读取输入值/Cookie、不注入 5+ 权限、不发业务请求，并恢复原网页标题。
30 秒内仍无内容则关闭子窗口，保留黑金欢迎页、当前域名和重试入口；重试重新
创建完整尺寸窗口，旧窗口/旧轮次事件不能覆盖新状态。附加子窗口仍不调用 show。

验证须包括缺失脚本导致的空 #app、正常 H5、失效事件及超时重试。浏览器与离线
事件测试不能代替 OPPO A72 / ColorOS 12.1 的 APK 真机验收。需重新云打包安装，
仅部署线上 H5 不能改变 2.5.06 APK 中的窗口逻辑。


## 远程调试开关（2.5.07）

Platform 公司配置的 App 设置提供默认关闭的“App 调试模式”，与版本元数据
一起保存，沿用 tenant.manage、公司锁、revision、确认与原子审计；无需提高版本号。
开关存放在既有 tenant_android_releases.metadata 中，不新增数据库迁移。
独立只读 GET /api/mobile/v1/app-debug 按当前域名解析公司，返回公司 ID/slug 和布尔
开关，no-store；无版本发布时默认关闭。此接口不依赖版本检查成功。

壳仅向已验证的当前公司域名查询，每 10 秒更新；单次请求最多 3 秒，失败或公司
不符即关闭，15 秒有效期兜底。进入后台即清空停止，回到前台重新验证，未开启时
不保留日志。开启后预留底部调试面板，展示脱敏当前地址/路由、状态、原生加载
事件、控制台级别及参数类型、异常类型/行列号、资源失败和 Promise 异常。
日志最多 60 条，仅本机内存，不写本地存储、不上传。网页 title 事件只传递白名单
结构；不展示原始参数、错误文本、Cookie、请求头/正文、查询参数或任意动态路径。
关闭时恢复 console 函数、移除监听和计时器、清空日志并恢复网页全屏尺寸。
诊断从远程开关验证成功后采集，不能追溯此前的错误。

部署匹配 PHP 路由/控制器和管理端 public/build 后，需要重新云打包安装 2.5.07；
旧 APK 不支持远程调试。无需重新部署业务 H5。后台开关以后无需重新打包。

### 父页面实测高度

静态对照页仍出现黑边后，子窗口改为使用父 `.shell` 的实际布局高度计算
显式像素高度（扣除一次顶部预留及可选调试区）。不使用 screenHeight，也不
依赖启动时可能为零的 windowHeight。首次读取不到有效尺寸仍用完整 top/bottom
布局，不写零高度；已取得有效值后零测量保留上次尺寸。250ms 内测量回调缺失
时使用已有边界，避免就绪网页永久透明。测量回调按窗口和轮次隔离。
尺寸变化、前台恢复和调试区切换会重测；开启现有公司 App 调试时记录
parent/top/height/bottom 数值，日志仅在本机内存中保留。

编译器当前强制产出 statusbar.immersed=supportedDevice，不能把修改源 manifest
当作关闭沉浸模式的证明。此次显式高度方案仍需原签名打包和真机冷启动验证，
离线尺寸模拟不等于已重现或解决黑边。H5 发布目录不包含此原生壳改动。

### 启动展示页伸缩试验（2026-10-09）

按用户要求将失败的 H5 登录页 viewport 缩放试验移除。现在在本地展示页仍
显示、远程内容已就绪时，让透明的 H5 原生子窗口缩短一次（最多 300px，
不超过当前高度一半），120ms 后恢复当前完整边界，再显示登录页。该操作
每次壳启动最多一次，不开启调试、不改变状态栏、不重新加载网页；失效窗口
和退出/失败后的回调不能显示旧内容。读不到有效高度时保留原有显示流程。

这是针对真机黑边的验证性改动，离线测试不能证明黑边已消失。需要重新云打包
本工程；public/h5 只包含撤掉登录页伸缩的版本，不包含原生窗口伸缩。
