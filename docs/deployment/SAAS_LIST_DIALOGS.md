# SaaS 列表与弹窗发布验收

平台端普通操作保留列表作为背景。用户行操作和公司配置按需读取已授权的 Inertia DTO；弹窗提交复用原业务 URL。`X-Admin-Dialog` 只选择响应格式，不授予权限。服务端仍使用 URL 中记录自身的公司、用户和原有权限。公司后台和用户端没有扩大查询范围。

## 页面清单

| 页面 | 默认入口与范围 | 新增／编辑或业务动作 |
| --- | --- | --- |
| 公司管理 | 公司分页列表，URL 搜索及状态筛选 | 新增公司弹窗；行内修改名称弹窗 |
| 公司配置 | 新增全公司分页概况，可筛选公司、状态、搜索及配置类别 | 品牌、语言、业务、文章、短信、邮箱、推广、理财、公司资金参数按需弹窗 |
| 公司产品销售配置／公司团队 | 从公司概况明确选择对应公司，保留现有公司列表 | 复用现有编辑／新增弹窗，不嵌套打开另一个配置弹窗 |
| 用户管理（含钱包） | 全公司分页与公司筛选，一位用户一行；按币种展示可用余额、冻结金额（移除钱包状态列），保留保证金、佣金及提现累计列 | 钱包、推荐人、推广等级、佣金操作使用共用弹窗；用户行提供充值／提现记录入口；原钱包 URL 验证权限及筛选后跳转到用户管理 |
| 合伙人 | 默认全公司分页，记录含公司身份 | 新增、编辑、预支、报销使用弹窗；存量报表和邀请数据使用右侧抽屉，报表分页与列表分页独立 |
| 通知 | 默认全公司已发送分页，带公司名称 | 新增弹窗内选一家公司，收件人随公司清空；预览确认在同一弹窗内完成 |
| 产品／卡商／域名 | 全平台列表及原权限，产品新增数据库分页 | 复用现有新增编辑弹窗，产品弹窗固定标题及操作区 |
| SaaS 管理员 | 全平台数据库分页 | 新增弹窗；不新增原业务未支持的编辑权限 |
| 客服人员 | 保留全平台分页 | 昵称编辑从行内打开弹窗 |
| 短信／邮箱配置档案 | 全平台数据库分页，不虚构公司归属 | 复用现有新增编辑弹窗，凭据保持只替换、不回显 |
| 卡片／充值／提现／KYC／财务记录 | 保留全公司列表及可选公司筛选 | 保留原业务操作、权限及审核工作区 |
| 登录／概览／客服会话／完整报表／全局单例配置 | 特殊工作区 | 保留专页 |

共用弹窗限制视口尺寸，固定标题和操作区，内容单独滚动；保存时锁定提交；字段错误保留输入；关闭未保存表单要求确认；焦点返回原入口。旧用户操作、创建公司和公司编辑链接跳转到列表的 `editor` 参数。该参数仅能加载同源白名单路径，刷新仍可重开，关闭保留背景列表过滤参数。后台列表分页不读取卡商。

详情优先采用右侧抽屉：合伙人存量报表、充值／提现订单详情、卡片消费记录已接入。标题固定，内容独立滚动，关闭返回列表原位置。存量报表通过 `partner` 与 `report_page` 保持可刷新链接，不改变列表 `company`、`page`、`fees_page`；入金／出金明细仍在当前抽屉内切换。旧报表链接保留兼容。预支／报销冲销表单打开时暂时收起报表抽屉，避免同时叠加两个操作面板。本项无需数据库迁移或 App 打包，部署匹配的后端和后台资源即可。

用户／钱包合并只调整平台展示。公司、账号、昵称、邮箱合并为左侧固定用户信息列，右侧操作列固定；其余列可横向滚动。钱包数据限定当前用户分页，批量加载并校验公司、用户、币种；没有 `wallet.read` 不返回该信息。USDT、USDC、ETH、BTC 不相加或换算，保留原生精度。列表查询不创建钱包；注册成功时自动开通零余额默认钱包，旧账号缺失钱包由登录后的认证 POST 补齐，已有停用钱包不重新启用。旧钱包入口额外要求 `users.read`，不自动给旧的仅钱包查看角色授予用户权限。本项部署后端与后台资源，无需迁移或 App 打包。

## 合伙人邀请数据

合伙人行的“邀请数据”按需请求 `GET /platform/partners/{partner}/invitations`，
沿用 `partners.manage` 平台权限；公司、用户由合伙人记录解析，显式公司不匹配返回 404。
表格复用用户端等级、直属／间接人数、年费及激活佣金统计，可展开拆分并查看每页 30 条
佣金明细（来源账号、邮箱、发奖时关系、来源金额、费率／级差、佣金和公司时区时间）。
当前人数按当前关系／等级，历史佣金按原始发奖证据；无等级来源的收入只在累计佣金计入。
URL 使用 `invitation_partner`、`invitation_kind`、`invitation_rank` 和 `invitation_page`，独立于列表分页。
抽屉支持失败重试、刷新恢复、关闭焦点返回，不调用确保推广成员的读写查询，也不创建钱包、
调用卡商或重新发奖。此项仅发布后端及后台资源，无需迁移或 App 打包。

## 佣金分类

- 新增调整必须选择激活、年费或历史佣金。后台输入有符号金额，内部端点仍使用正金额与增减方向。
- 复用公司锁、钱包锁、LedgerWriter、权限、请求 UUID、金额精度及余额限制。所选类型、累计佣金和可用余额均不得扣成负数。
- 原调整和账本不可变；`commission_adjustment_classifications` 保存不可变类型、前后类型净额、操作人、原因、请求编号及时间。
- 历史未归类记录在后台过滤“待归类”，逐笔补选。此操作不写账本、不改变原入账时间，分类只允许一次；重复相同请求返回原结果。
- 用户端仅显示对应佣金类型。未归类历史记录显示“佣金”。后台标识、操作员及内部原因不会进入用户 DTO。
- 个人核对按对应分类累计；历史佣金继续纳入激活类核对口径，另有 `unclassifiedCommission` 承载未归类净额。团队存量仍按原业务来源过滤，不把后台调整归入某个下级。

## 发布顺序

1. 备份后，在发布窗口执行 `php artisan migrate --force`，包含 `2026_10_05_000001_classify_commission_adjustments.php`。不执行历史佣金自动归类，不修改历史资金。
2. 同步部署匹配的 PHP 代码与 `public/build` 后台资源，刷新配置／路由缓存，并重启使用旧代码的常驻进程。
3. 发布匹配的 uni-app H5 资源。需要新佣金文案和报表展示的原生 App 另行重新打包。
4. 用有权限的测试管理员只读验收列表及弹窗；线上不以补发、扣减、群发或真实卡商操作测试界面。

迁移审计表不能通过 down 删除；回退应用时保留新证据。界面改造本身没有新增数据库表。所有财务验证仅在隔离的 `card_ui_test` 数据库执行。

保存成功关闭并刷新原列表；空响应、版本变更与登录过期显示可读提示，不自动重放操作。
