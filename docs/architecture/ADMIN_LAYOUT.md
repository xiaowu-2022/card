# SaaS 后台布局与操作复盘（2026-10-04）

## 检查范围与证据

检查当前本地后台构建和现有测试数据，包括客户、卡片、充值/提现订单、资产设置、OSS、产品、合伙人、公司、卡商、客服。未登录生产后台，未执行资金、卡商或配置变更；本地响应时间不能代表线上性能。

1366×768 下，原客户列表共 14 列，表格约 1658px、可视区域 1028px，多个操作入口在屏幕外。卡片列表每行堆放 5 个操作，实测行高 261px，13 条记录的页面高度约 3953px。页面本身未溢出不代表表格易用，原来的整页宽度断言无法发现这些问题。

## 本轮已实现

- SaaS 主内容最大宽度 1600px，窄桌面窗口仍随可用区域收缩。
- 共用账户列表移除重复横向滚动容器，操作列固定右侧并使用不透明背景；表头与数据列同步固定。
- 普通文本单元格限制为 208px，超长内容省略，鼠标停留可查看完整值；金额组件保持原精度和显示规则。
- 客户的实名认证、钱包调整、推荐人和手动佣金入口合并为一个操作菜单，继续按各自权限显示。
- 卡片保留“查看流水”，其余操作收入“更多操作”；原确认、密码和接口规则保持不变。弹窗关闭后焦点回到该行菜单按钮。
- 共用弹窗增加视口高度上限和内部滚动；系统设置标签页可横向滚动；资产设置吸顶工具栏避开 64px 顶栏。

三种桌面宽度 1024、1366、1920 下，卡片测试记录行高均为 69px。共用列表覆盖客户、卡片、充值订单的固定列验证。未更换其他独立表格的全部结构，不能宣称整个后台已完成重构。

## 后续优化建议

1. 客户详情与返回列表保持搜索、状态、页码及滚动位置。当前钱包/推荐人等页面的“返回用户”只携带公司，会丢失原筛选上下文。
2. 已补齐卡片页选项卡 URL 状态，刷新/后退恢复原位置。同步入口统一支持单卡、勾选卡片和公司范围，任务进度直接显示在列表上方；浏览器逐页推进，离开后手动继续。
3. 卡片数据按所选页签加载。当前查询同时分页读取开卡、充值和卡片数据；需结合线上请求耗时与 SQL 证据评估优化效果，不能据此直接判定线上卡顿根因。
4. 后续逐步将独立产品、公司等表格纳入同一列宽、操作列、加载反馈规范；将验收从“没有整页溢出”扩展为“常用操作可见、行高合理、短窗口可操作、返回不丢上下文”。
