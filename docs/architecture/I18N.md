# Internationalization

Tenant-authored About articles are stored per tenant/key/locale. Resolve the exact
enabled consumer locale; a missing translation shows a translated empty state,
never another language's content. Admin chrome and article content language are
independent. See [TENANT_ARTICLES.md](TENANT_ARTICLES.md).

The consumer and tenant-public surfaces use `i18next` + `react-i18next`, with the existing project primitives. Their supported locales remain `en`, `zh-CN`, `ms`, and `es`. Tenant Admin and Platform Admin use the same instance with a dedicated `admin` namespace, supporting only Simplified Chinese (`zh-CN`, default) and English (`en`).

## Administrator language contract

`ResolveAdminLocale` runs after trusted Host/Tenant resolution and before Inertia. Both Admin surfaces default to Chinese, regardless of browser language, Tenant consumer enabled locales, or User preferences. A valid encrypted Admin cookie takes precedence. Platform hosts are never resolved as ordinary Tenant domains.

`POST /admin/locale` and `POST /platform/locale` are guest-accessible display-preference endpoints (login and invitation screens need a selector). They retain web CSRF, same-origin credentials, 30/minute throttling and the existing tenant-admin lifecycle policy. They accept only `zh-CN`/`en`; client identity selectors are prohibited. They do not grant authentication or mutate any identity, membership, Tenant setting, User preference, business order, or money.

The encrypted, HttpOnly, host-only cookies are `admin_locale_{resolved_tenant_uuid}` with `/admin` path and `platform_admin_locale` with `/platform` path. Both use SameSite=Lax, one-year expiry and Secure on HTTPS. Language is a browser preference, not an authorization or tenant-switching mechanism. Consumer cookies and persistence remain separate.

`admin-catalog.ts` supplies Admin translations plus explicit human-readable system status/role labels. Stored enum values, select values, URLs, permission checks, assets, IDs and exact decimal strings remain unchanged. Shared primitive labels reuse the existing common catalog. User-authored names, products and review messages remain content and are not auto-translated. Safe known errors are translated; unrecognized errors use the localized safe fallback.

`AdminLanguageSwitcher` appears in both authenticated layouts and `AdminAuthLayout` (login/invitation/error screens). It saves the preference with CSRF protection, then changes the existing i18next instance without navigation, form remount, or business-request replay. Failed saves leave the current language intact. Date displays use the chosen language and trusted Tenant timezone. No extra UI framework or database migration is needed.

## Resolution and persistence

`Host -> tenant_domains -> TenantContext -> ResolveUserLocale` precedes the consumer Inertia middleware. It chooses the first enabled, application-supported value from:

1. The authenticated User's tenant-scoped `user_preferences.locale`.
2. The encrypted, host-only, HttpOnly `user_locale_{resolved_tenant_uuid}` cookie.
3. `Accept-Language`, including regional/base-language matching.
4. The enabled `tenant_locales.is_default` row (not a client or legacy default override).

Unsupported or disabled preferences are ignored. Tenant configuration must retain at least one enabled default, as already required by Tenant onboarding. No IP geolocation, forced country-based switching, or external translation service is introduced.

`POST /locale` accepts only a language selection. The request uses the existing web CSRF/session protection, user host/session isolation and `user-auth` lifecycle policy, plus a 30/minute limiter. Client `tenant_id` and `user_id` are prohibited. The action locks Tenant before User, rechecks the enabled locale, and updates only the current tenant User's existing preference. Guests receive only a cookie; suspended users may change language without gaining operational access. DRAFT/CLOSED availability is unchanged. The host-only cookie has SameSite=Lax, one-year expiry, and Secure on HTTPS. It is a preference, never an identity or tenant-selection authority.

No migration, money mutation, business state, registration bypass, or provider call is added. Registration's existing preference field receives the selected locale. Inertia shares only locale, enabled locale codes and the tenant timezone. Laravel's request locale is restored after the response to avoid leaking into later requests.

## Frontend contract

`resources/js/i18n/catalog.ts` contains whole-sentence English keys with complete Chinese/Malay/Spanish tuples. `resources/js/i18n/index.ts` initializes the instance before the first render. Every translated consumer component subscribes through `useClientTranslation`; `t` reads the active instance. Named interpolation placeholders must match across all four languages. Never concatenate translated sentence fragments.

The globe button on consumer headers and the Me > Language item are real selectors, using only server-enabled locales. Native language names identify choices deliberately. Saving uses a CSRF-protected same-origin request and changes the language without navigation or remounting: partially entered forms and stable financial request IDs are preserved. The next page/reload resolves the persisted preference. A failed save leaves the current language intact and displays localized feedback.

Activity labels, human-friendly states, titles, controls, confirmations, validation messages and safe feedback use the catalog. Money remains exact decimal-string data rendered by the existing `MoneyDisplay`; never parse or recalculate it with JavaScript numbers for localization. Dates use the selected locale and tenant timezone via `Intl.DateTimeFormat`. Card expiry is the provider's display field, not a timestamp to convert.

Tenant branding, product names, personal names, custom destination labels, reviewer-authored KYC feedback, masked card data, assets/networks, addresses and transaction identifiers are content, not translation keys. Preserve them verbatim. The explicit TEST/MOCK markers remain unmistakable. Never translate enum values, routes, resource IDs or Ledger event keys.

Explicit display-name exception: the default `Mille Card` product is presented to consumers as `U Card` / `U 卡` / `Kad U` / `Tarjeta U`. The letter `U` is invariant. `cardDisplayName` applies this exact alias (also recognizing `U Card`) consistently to owned cards, application dialogs, product options and introductory copy; other custom product names remain verbatim. This presentation-only rename does not change persisted product names, IDs, provider references or administrator views.

Known safe server messages and bounded Laravel validation templates are translated at the presentation boundary. Unknown errors use a localized safe fallback rather than displaying raw provider or technical text. Translation never changes domain exceptions or financial transition semantics. Add new safe messages to the catalog as business flows evolve.

## Acceptance checks

`npm run test:i18n` checks all four catalog resources, interpolation parity, literal consumer translation-key coverage, untranslated JSX/accessibility copy, every Wallet activity mapping, exact decimal preservation, actual language switching, date formatting and validation/fallback behavior. It is included in CI alongside typecheck, lint, format and build.

`UserLocaleTest` exercises locale priority, enabled-language enforcement, regional browser matching, persistence, tenant/session isolation, prohibited client selectors, host-only cookie properties, lifecycle restrictions and Admin isolation. Run PHP tests against the separate local test database, never the populated demo database.

`AdminLocaleTest` covers Chinese defaults, independent language catalogs, encrypted cookie round-trip and path/host properties, invalid locale/selector rejection, consumer separation, membership and platform scope, lifecycle and CSRF protection. Frontend tests enforce Admin key coverage, untranslated JSX/accessibility checks, enum display, interpolation and safe feedback. `tests/Browser/admin-i18n.mjs` checks both languages at 375/768/1440 px, persistence across navigation/reload, and preservation of unsaved login/business forms; it never submits a business mutation or resets fixtures.
