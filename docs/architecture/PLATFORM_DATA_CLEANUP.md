# 指定账号测试数据永久清理

2026-10-11 用户明确授权的专用历史删除例外。入口位于 SaaS 用户管理的“清理数据”，公司后台不开放。所有有效平台管理员均可使用，仍校验有效账号、平台成员身份及公司范围。迁移、部署和定时维护不会自动选择或清理业务数据。

## 范围与依赖

选择一个公司、1–50 个账号，以及账号整包、订单、佣金、卡片中的一个或多个项目；不采用时间截止、真实/模拟标记。整包强制包含全部项目，有下级则阻止执行，即使同时勾选下级也不绕过限制。先通过现有推荐人变更流程迁走下级。

`CleanupSchema::TABLES` 是明确的业务表清单。`ORDERS` 包含主钱包及多币种充值、提现、转账、兑换、保证金、代理年费、年返、理财、余额调整；开卡和管理订单也属于订单范围。`COMMISSIONS` 包含收到的佣金、佣金提取/归并、人工佣金和分类，以及被选账号活动产生的奖励事件、各收款人的佣金。`CARDS` 包含独立加密持卡资料、卡片、开卡/管理订单、收件资料、交易、通知、溢出资金及同步记录。

按数据库实际复合外键展开子记录，并按业务关系补齐奖励来源、年费周期、预支合作日志、到账类型变更、链观察及通知。删除任一资金分录时展开全部记账项；其他业务引用及冲正分录也必须完整纳入清单。其他账号可有关联记录和余额变化，但其身份不会自动删除。新增未登记模块的外键依赖阻止执行，不依靠数据库静默级联。

同步批次只剩被选账号卡片时连同批次删除；涉及其他账号或公司的共享批次保留头部和其他卡片项，只删除被选卡片的项。继续执行共享批次不会重新生成被删项。

整包还包括资料、认证、设备/浏览器登录凭据、推广成员及历史、合作方、客服授权/回复/消息和通知。管理员、公司设置、商户、共享产品、定价和操作审计始终保留。卡片清理只处理本系统记录，不请求注销、退款、查询余额或资金转移；外部卡片仍由服务商管理。

## 预览、事务与账本

预览使用一致数据库快照，存储不可变精确清单：批次、表、主键 JSON、整行哈希、删除或邀请码保留操作。展示分类/表数量、连带数量、受影响账号、原生小数字符串余额前后值，以及可分页查看的安全记录清单；不返回密码、认证图片、解密资料、服务商密钥或备份路径。预览有效十分钟。

执行只接收批次编号、请求 UUID、明确确认。先取得公司排他业务互斥及稳定顺序的业务表锁，再校验操作者、完整清单指纹、余额和在途状态。有并发业务时返回稍后重试；预览后新增/改变订单、清单行或相关余额时要求重新预览。业务表锁会短暂阻止其他公司的同表写入，读取不受影响。HTTP 及队列业务持公司共享互斥；浏览器批量同步的服务商请求也持共享互斥。已有支付发起租约或近期仍在执行的持卡/开卡/管理/同步操作阻止清理。

执行前将所选完整原始行、余额和图片引用压缩并用 Laravel APP_KEY 加密，写入私有磁盘 `data-cleanup/<批次>.enc`，校验写入及 SHA-256，默认保留七天。备份失败不删除。APP_KEY 必须保留，备份不可发布至 public、浏览器或普通日志。删除失败可能留下加密孤立文件，七天后维护任务清除。

在同一事务内写删除标识、删除精确预览行、重算保留账户、记录图片清除意图和不可变操作审计。重算以剩余封存记账项之和为准，使用 PostgreSQL numeric 和 BigDecimal，支持 ETH 18 位等原生精度。先核对当前余额缓存与账本；清理后用户账户或受非负约束公司账户为负则阻止，不补偿、不注入虚构流水。执行后强制检查全部延迟约束，再完成批次；任一步失败全部回滚。

同一操作者、批次和请求 UUID 的成功重试返回原结果；换 UUID 或把 UUID 用于另一批次冲突。批次及清单禁止改写，完成后的审计和永久标识继续保留。

## 数据库专用例外与防复活

`cleanup_manifest_allows` 同时核验当前事务本地批次、执行状态、数据库 backend PID/transaction ID、有效平台管理员、已验证备份指针、公司、表、主键及整行哈希。仅此精确 DELETE 例外可穿过原不可变历史触发器。普通更新/删除禁令继续执行，不设置复制角色、不关闭触发器或外键。业务表之间的外键保留其原始检查时机，允许此事务延迟循环依赖，但最终仍全部检查。

账号编号永久保留，分配器跳过已清理编号。邀请码全局保留记录将 member FK 脱离至清理成员编号，不释放号码。行主键、业务请求、Ledger 事件、佣金来源、外部支付/链收据、商户范围的持卡/卡片/服务商请求标识永久保留哈希；新增/更新数据库守卫禁止重用。

队列提交后有界移除数据库/Redis 中相关待执行任务，保留其他任务及工作中任务；维护定时重试。工作器执行前再次检查标识，即使队列暂时不可用或任务迟到也会丢弃。恢复流程读取不到已删除资源；佣金分配、TRC20 匹配、多币种扫描/人工核实、支付与卡片回调识别永久标识。回调仍先验证原签名，再对已清理资源确认接收，不新增订单、事件或资金。

私有图片不随数据库删除立即移除。七天后维护任务检查全部公司的剩余业务引用，确认无人引用才通过既有 ImageStorage 异步清除。共享或仍被引用的图片保留。

## API 与部署

平台路由前缀 `/platform/tenants/{tenant}/data-cleanup`：GET `accounts` 搜索账号；POST `preview`；GET `{batch}` 查询状态；GET `{batch}/records` 分页安全清单；POST `{batch}/execute` 确认执行。接口权限为平台 `users.read` + `users.cleanup`，不存在公司后台对应路由。状态 GET 与预览不执行删除。执行同步完成；界面显示忙碌状态，网络结果不明可通过状态 GET 恢复并使用原 UUID 重试。

部署新迁移 `2026_10_11_200000_add_scoped_platform_data_cleanup.php`、PHP 与后台构建资源，重启队列工作器及 PHP 长驻进程。确保现有私有磁盘可写并正常运行 scheduler，小时任务 `data-cleanup:expire-backups` 清除过期备份/无引用图片并重试待执行任务移除。迁移不删除任何账号、订单或资金记录，不调用服务商；不要运行 Seeder、migrate:fresh 或自动执行清理。

## 隔离验收

`PlatformDataCleanupTest` 覆盖整包、分项、完整转账、双向佣金、下级/跨公司阻止、ETH/BTC 精度、负余额、账本重算、陈旧/过期预览、双连接并发、请求幂等、备份失败、事务回滚、凭据失效、任务移除和七天保留。`CardIssueTest` 中清理用例复用离线服务商替身，覆盖开卡/充值/交易/同步和共享产品保留。浏览器离线 fixture 验证入口、确认、记录详情、阻止状态及请求范围。数据库测试强制使用 `card_ui_test`，禁止实际清理和外部金融操作。
