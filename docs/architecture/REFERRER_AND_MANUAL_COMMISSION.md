# SaaS 推荐人修改与手动佣金

2026-10-04 用户批准新增两个平台操作。此规则仅在明确授权的后台入口覆盖历史“推荐关系不可修改”约束；普通注册、用户接口及其他身份字段仍不可修改。既有佣金不因换推荐人追回或重算。

## 后台操作

客户列表提供“修改推荐人”和“手动佣金”。前者需要 `users.read` + `users.referrer.manage`，后者需要 `users.read` + `wallet.read` + `commissions.adjust`。迁移增量授予平台 Owner/Admin，租户管理员不会获得这两个权限。

推荐人页面按账号或邮箱搜索同公司有效用户，展示当前推荐人、目标推荐人、随行下级人数。只更换本人直属边，下级之间关系不动；拒绝清空、自身、后代及跨公司目标。请求包含旧推荐人、关系版本、UUID、原因及确认。公司锁与现有业务结算串行化；事务内复核权限和关系版本，过期表单返回 409。

`referrer_changes` 保留不可修改的前后关系、版本、操作者、原因及时间。数据库要求关系修改存在同事务匹配记录并递增版本，同时保留循环检查和身份不可变规则。推荐码不变。当前团队读模型立即采用新树；已经记录的激活业绩、返还快照、佣金与账本不改写。新业务按结算时关系计算；已完成业务重试仍复用原记录。

历史佣金关系优先使用已有结算深度快照。旧活动展示依据变更历史还原事件时推荐人；由于旧事件只有秒精度，同秒发生变更时不猜测先后，推荐关系显示未记录。

## 手动佣金

固定 USDT，金额为正、最多八位小数，方向为补发或扣减，必须填写原因及确认。只操作有效公司、有效用户的已有有效 USDT 钱包，不创建、恢复或激活钱包。

`manual_commission_adjustments` 保存调整方向、金额、钱包及佣金净额前后值、操作者、UUID、原因和账本关联。由 LedgerWriter 以 `MANUAL_COMMISSION` 事件记入本人 `USER_AVAILABLE` 与公司 `TENANT_COMMISSION_CLEARING`，账本和业务证据在同一事务提交；数据库验证恰好两笔作用域和金额一致的记账分录。记录禁止修改或删除，纠错需另一笔调整。

扣减上限为 min(USDT 可用余额, 全部累计佣金净额)，包含去重后的历史佣金、激活／年费佣金及手动调整。扣减后钱包及总佣金净额不能负数，但独立“手动佣金净额”可以负数。公司、用户及账本锁保证并发扣减重新检查当前额度；相同 UUID 重试复用结果，改变意图返回冲突。

普通用户报表只获得金额、类别、入账时间等安全字段，不获得内部原因或后台操作员信息。新增操作不会触发激活、升级、年费返还、站外通知或卡提供商调用。

## 报表兼容

- `PromotionReportQuery::income` 新增 `manual` 类别，无下级业务来源／等级／深度；累计收入、每日数据及佣金明细包含带方向净额。
- 公司资金账簿的 `manualCommissions` 与 `commissionCost` 使用有符号净支出，不能对手动扣减使用绝对值。
- 钱包流水标签为“手动佣金”；SaaS 客户累计佣金列同步包含手动调整。
- `accountBalance.manualCommission` 是八位小数字符串。个人理论余额加入该净额，实际钱包余额同步变化；其他业务不变时差额保持不变。
- 原团队存量依旧按业务来源归属统计；没有业务来源的手动佣金不分摊给下级，不纳入原团队存量公式。
- 现有返回字段保留，新类别与字段为增量扩展。更新后台、H5；原生 App 需要新报表展示时重新打包。

## 发布和验证

部署代码与后台／H5 构建资源。维护窗口先执行迁移，再启用新页面：

```sh
cd /www/wwwroot/card
/www/server/php/84/bin/php artisan migrate --force
/www/server/php/84/bin/php artisan optimize:clear
/www/server/php/84/bin/php artisan config:cache
/www/server/php/84/bin/php artisan queue:restart
```

迁移只增表、约束、关系版本及权限，不修改旧关系，不转账，不补发历史佣金。生产不运行 seed 或测试。历史不可删除，因此迁移不支持破坏性回滚。

离线测试包括数据库证据约束、跨公司隔离、重复请求、权限撤销、子树转移、旧佣金保留、新业务归属、八位精度、负手动净额、扣减额度、真实多进程竞争及个人／团队报表口径。使用隔离的 `card_ui_test`，不执行真实金融交易。
